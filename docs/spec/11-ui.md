# 11. UI 構成

- **UnifiedMap**: 単一の SVG Voronoi マップ（過去の二段階マップ StateMap + ProvinceMap を統合済み。ReactFlow (`@xyflow/react`) は不使用）。zoom level に応じて State / Province の表示強度を自動切替
  - **Far zoom（State レベル）**: Province セルを State の dominant polity 色で統一表示。State 名 + 人口 + unrest ラベル。State クリック → そのエリアにスムーズズームイン
  - **Medium zoom（遷移）**: Province 単位の polity 色。Province 名ラベル・アイコン（小）・neighbor edge を表示。Province クリック → DetailPanel を開く
  - **Near zoom（Province 詳細）**: Province アイコン（都市/農村 + 城/荘園バッジ）フルサイズ表示。Province クリック → DetailPanel を開く。ホバーでツールチップ（名前/State/Polity/人口/unrest/Holdings数）
  - セル色表現: 薄い半透明 fill + 枠線に polity 色（地図の雰囲気を保持）
  - 外枠: ocean ダミー点（Province 群の凸包外側に配置）による不規則な輪郭
  - mapView 切替（T/R/H/%/!）: terminal polity / root polity / owner house / owner-house influence（v0.42: 旧 share view） / unrest heatmap
  - highlight tier: DetailPanel で Polity/House 選択時に関連 Province をハイライト（direct/indirect/none）
  - ズームコントロール: +/-/reset ボタン（左下）
- **Sidebar**: 人物一覧。重要度スコア順。ウォッチリスト対応
- **DetailPanel**: 選択エンティティ（Province / Polity / House / Person / PopGroup）の詳細表示
  - **ヘッダー画像**（terrain/設備連動。`app/utils/assetHash.ts`）: Province / Holding の詳細ヘッダー（および Province 内 Holding カード）の画像を内容に応じて選択する。
    - Province（terrain 5 × 水状態 4 = 20 枚）: terrain（平野/森林/丘陵/山岳/湿地）と水状態を組み合わせる。水状態は「沿岸（coastal）」と「河川（major_river または lake）」の独立 2 軸（なし / 河川 / 沿岸 / 沿岸＋河川）。該当画像が無ければ terrain ベースへフォールバック。
    - Holding（荘園 2 + 都市 4 = 6 枚）: 荘園は牧畜（pastoral）の level が農地系（field_system / irrigation の最大）を上回るときのみ「牧畜」、それ以外は「農地」（設備なしも農地が既定）。都市は market & workshop 両方→「大都市」/ market のみ→「市場」/ workshop のみ→「工房」/ どちらも無し→「基本」。`storage` / `transport`（生産品質系）は画像選択に用いない。
  - ProvinceDetail:
    - **地形** セクション: terrain（単一値）と features（`, ` 連結、空なら `—`）を表示。i18n key は `detail.province.terrain_value.*` / `detail.province.feature_value.*`
    - **Holdings** セクション: 各 Holding をカードで表示。name / kind badge (manor: 緑, city: 琥珀) / development（getHoldingDevelopment selector 経由）/ polityControl / landQuality / weight / per-Holding LandContract chain (各 grantee Polity をリンク付きで表示) / **Improvements**（フレーバー名を主表示、カテゴリ+レベルを括弧内に補助表示。flavor→category→kind のフォールバックで生キーを出さない。例: storage は `納屋 （貯蔵基盤 Lv.1）`、flavor 未定義の新 kind は category 名のみ `農地整備 （農地整備 Lv.2）`）/ **occupation capacity**（class 別に employed / cap ＋ unemployed を表示）/ **active develop_holding Project**（stage / progress / budget 表示）/ Bailiff 詳細:
      - 代官名（person リンク）/ placeholder / vacant
      - 代官任命権保持者（v0.42 — HoldingDetail の Bailiff セクションに `RightHolderLine` で表示。right 無し = 非表示）
      - BailiffPolicy（色分け: passive=灰, loyal_remittance=青, profit_seeking=橙, protect_residents=緑）
      - localExtractionRate / collectionEfficiency / bailiffFeeRate / totalBurdenRate / collectionFrictionBurdenRate（%表示）
      - 直近 Task status（completed=緑, none=灰）
      - POP→代官平均 Attitude（affection / respect）
    - **Population** セクション: Carrying Capacity / Total Population / Pop. Pressure（90% 超で赤表示）/ Avg Wealth / Unrest（60 超で赤表示）/ Production / Polity Manpower
    - **POP Groups** セクション: class 別に size / wealth / unrest（60 超で赤表示）を一覧表示。各 POP カードはクリッカブルで PopGroupDetail へ遷移
    - **Revolt Risk** セクション: class 別反乱傾向値（Peasants / Townsmen / Nobles）
    - development / polityControl は Holding の weight 加重平均で Province レベルに集約表示
  - PolityDetail:
    - 基本情報: Ruler（人物リンク）/ Royal House（getPolityLeaderHouse）/ Dominant House（getDominantPolityHouse）/ 首都 / Legitimacy / Treasury / Military Power
    - **Administration** セクション: Capacity / Load / Efficiency（getAdministrative* セレクター）
    - **Roles** セクション（v0.42: 2 列カード化 + slot 行表示）: leader / administrator / treasurer / military / advisor の役職カードを 2 列 grid で表示。leader は担当者リンクのみ（slot 概念なし）。他 role は slot 0..effectiveMax-1 ごとに「席番号（`第{{n}}席`）+ 着座者リンク（空席は「—」）+ その slot の任命権保持者（`RightHolderLine` — right 無し = 統治者の本来権限 = 非表示）」を縦に並べる。effectiveMax を超えた slot に残る着座者（縮小直後の過渡）も行として出す。rank で許可されない役職は slot 0 件で「—」表示
    - **Influence** セクション（v0.42 旧 Top Shareholders → 影響力個人中心化で**家グループ二重円**に再設計）: Polity Influence を**家の支配率（§6.64a-(10)）単位にグループ化**して表示する（`getGroupedPolityInfluence`）。
      - **二重ドーナツ**（`NestedDonutChart`）: 外周＝各家の支配率（家本体＋家中メンバーの合算）、内周＝その内訳（家本体＋各メンバー個人）。外周のグループ角度と内周セグメント角度を同じ並びで連結し、同一家を同色相の濃淡で示す。中心に支配的な家名＋家の支配率を表示
      - **リスト**: 家ごとに見出し（家の支配率% ＋ 家全体の domain 内訳上位 3 を 1 行）→ 家本体（「家本体」ラベル）・メンバー個人（Person リンク）を influence 降順でぶら下げる。家を持たない有力 Person は単独グループ（見出し＝ Person リンク・内訳行なし）
      - 家の支配率が一定%（UI 定数 `INFLUENCE_LIST_MIN_GROUP_PERCENT`、既定 3。`SimulationConfig` ではなく表示専用定数）未満の家・家無し個人は「その他」に集約
    - **共和国の権力分布** セクション（v0.46 §6.68）: `isEstablishedCommonwealthRepublic` の polity（共和国）のときのみ Influence セクションの直後に表示（`RepublicPowerProfileSection`、`getRepublicPowerProfile` 直呼び）。最有力者（topPercent）/ 上位 3 者合計 / 実効権力者数（Herfindahl 逆数）/ 指導者影響力 / 役職支配 / 任命権保持を holder（Person / House）リンク付きで表示。topPercent が `republicDominantHolderThreshold`（既定 60）以上の top holder は「支配的」バッジで視覚強調する（UI のみ・event は出さない）。i18n key は `detail.polity.republic.*`
    - **Houses with land here** リスト: その Polity に Province を 1 つ以上持つ active House を、Polity 内 Province 数とともに表示。primary がここでない House には「non-primary」マーカーを付ける
    - **Current Goal** セクション: GoalKind（i18n）/ DecisionReason 一覧 / progress / targetProgress
    - **Active Aim** セクション: AimKind（i18n）/ progress / targetProgress / deadline
    - **Active Task** セクション: TaskKind / effort / 担当者
    - **保有連隊** セクション: Polity が所有する **active** Regiment を一覧表示（`getRegimentsForActor(state, {kind:'polity', id})` → `status === 'active'` filter）。土地契約一覧の直後に配置。各連隊に **連隊名**（由来 Province 名 +「連隊」。`homeProvinceId` 未設定時は ID フォールバック）/ **組織率**（organization）/ **士気**（morale）/ **充足率**（strength）を表示。organization / morale は現在値とともに baseline（`current/baseline`）を併記表示する（reg_baseline_hint 注記付き）。strength は単独表示。同一 Province 由来の複数連隊（1 Province 複数 Holding）は同名でフラットに並べる。destroyed（再編成待ち・strength≈0）と disbanded（恒久解散）は観賞用スナップショットの主旨に合わないため除外。連隊詳細パネルは未実装（名誉職的な扱いと同様、今後の作り込み対象）。v0.42: 2 列カード化し、各カードに `regiment_control` right 保持者を「管理権」行で併記（`RightHolderLine`。right 無し = 非表示）。土地契約カードにも terminal 契約行に現職代官 + 代官任命権保持者を併記する
  - HouseDetail:
    - 基本情報: Leader（getHouseLeader）/ 本拠地 / Province 数 / Wealth / Prestige / Military
    - **構成員** セクション見出しの右に「家系図を見る」ボタン。store の `openFamilyTree(houseId)` を呼び、家系図 overlay（後述）を開く
    - **Offices** セクション: administrator / treasurer / military / advisor の担当者リンク（空席は「—」）
    - **家中シェア（House Share）** セクション: House Share 上位 5 Person と割合（v0.42: Polity Influence と混同しないようラベルを明確化）
    - **保有する任命権** セクション（v0.42）: 家保持の PoliticalRight + 生存 member の個人保持分を一覧（Polity リンク + target ラベル。office right は「役職名 + 第{{n}}席」、個人保持分は holder Person を併記）。表示順: 役職 > 代官 > 連隊 → ラベル昇順
    - **Clan** セクション: 所属 Clan 名（クリックで ClanDetail 遷移）/ Clan 内の立場（root / descendant）
    - **Current Goal** セクション: GoalKind（i18n）/ DecisionReason 一覧 / progress / targetProgress
    - **Active Aim** セクション: AimKind（i18n）/ progress / targetProgress / deadline
    - **Active Task** セクション: TaskKind / effort / 担当者
  - PersonDetail:
    - 基本情報: Age / **Life stage（人生段階ラベル。age の直下。i18n `life_stage.*` ns:statuses）** / House / Sex / Birth Status / Wealth
    - 成人・老年入りの life event は個人 Chronicle セクション（履歴）に残る。主要人物の場合はメイン EventLog にも表示される（§6.25 / §8）
    - **Life Goal** セクション: PersonGoalKind（i18n）/ fulfillment（currentFulfillment / 100）
    - **Current Pursuit** セクション: active PersonAim（AimKind / progress / deadline / waiting 状態表示）
    - **Assigned Tasks** セクション: effectivePriority 降順で表示。各 Task に kind / effort / P:値 / target 名（owner の house/polity 名付き）
    - **Recent Activities** セクション: PersonActivityLog 直近 5 件。TaskActivityLog（week / taskKind / outcome）と ProjectActivityLog（week / projectKind / kind、params に improvementKind / targetLevel / holdingId があれば併記）を kind で分岐表示。i18n key: `activity.project_completed` / `activity.project_failed`
    - **Offices** セクション: Polity と House でグループ分け、役職重要度順（leader → administrator → treasurer → military → advisor）。代官職（HoldingOfficeAssignment）を持つ場合は任地 Province 名リンクと BailiffPolicy（色分け: passive=灰, loyal_remittance=青, profit_seeking=橙, protect_residents=緑）を表示
    - **保有する任命権** セクション（v0.47.4）: この人物個人が保持する PoliticalRight を一覧（`getRightsByHolder` の `{ kind: 'person', id }`。Polity リンク + target ラベル。表示順は HouseDetail と共通の `sortRightRows` = 役職 > 代官 > 連隊 → ラベル昇順）。保有者は常に当該人物なので holder 列は出さない。HouseDetail の「保有する任命権」が家保持分 + 生存 member 個人保持分の両方を出すのに対し、本セクションは当該人物個人分のみ。right 無しは「—」表示
    - Stats / Traits / Family リンク / **Attitudes セクション**
  - **PopGroupDetail**: size / wealth / unrest（60 超で赤表示）/ 所属 Province リンク / **Attitudes セクション**
  - ClanDetail:
    - ヘッダー: Clan 名（nameSourceHouseId の House 名から派生）/ active or extinct バッジ
    - 基本情報: ID / 成立日 / root House（リンク）/ founder（リンク、存在する場合）
    - 統計: active House 数 / extinct House 数 / 生存人数 / 総資産 / 総威信 / 支配家門数
    - 所属家門一覧: root House（ラベル付き）→ active descendant → extinct descendant（dimmed）。上限 10 件 + "+N more"
  - DiplomaticPlayDetail: initiator / target の delegate 名、preparation / leverage / commitment パラメータ、active Task 一覧、tension / progress。**v0.43**: initiator / target 各 side の支援国行（`initiatorSupporters` / `targetSupporters` を PolityLink で列挙。supporter は delegate / preparation 等を持たない）
  - WarDetail: DiplomaticPlayDetail の縮小版（交渉系要素なし）。status バッジ（active=赤 / attacker_won・defender_won=緑 / white_peace・cancelled=灰）/ attacker / defender（actor.kind で polity・house リンク）/ **warScore バー**（-100..+100 の綱引き表示。中央 0、攻撃優勢=右/緑・防衛優勢=左/赤、±targetWarScore に黄マーカー、現在値を白マーカー、数値は `+N / 決着 ±target`）/ 開戦・終戦（year/month/weekOfMonth）/ warGoals（土地割譲 / 税率改定、対象 holding・Province リンク。税率改定は **開戦時に凍結した `baseTaxRateToGrantor` → `newTaxRateToGrantor`** を表示し live 契約税率を読まない。これにより終戦後＝税適用済みでも「元→新」が正しく残り、X%→X% に見える混乱を防ぐ）。attacker / defender 各陣営の**総大将**（`captainGeneralPersonId`、Person リンク。不在は「—」）・**指揮官候補**（`commanderPersonIds`、Person リンク列）・**回避回数**（`avoidanceCount`）を表示する。最近の戦闘イベントは WarDetail には表示しない（Chronicle の「戦争の記録」が永続的な履歴を担当するため）。EventLog では BATTLE_OCCURRED=⚔ / BATTLE_AVOIDED=🛡 / WAR_CAPTAIN_GENERAL_CHANGED=🎖 の icon。戦場種別（battlefieldKind）は戦闘ログ内で戦闘類型名（〜戦）として label 化（terrain 属性ラベルとは別概念。§8）。attacker / defender 各陣営の**動員連隊数**（当該 War/side の active Regiment 数）と**連隊戦力**（`getRegimentPowerForWarSide`。§3.9b）を指揮ブロックの直後に表示する（指揮ブロックと同じカード体裁）。戦闘イベントの本文には動員連隊数（`{attacker} 対 {defender}`）が出る（counts-only enrich。§8）。**v0.43**: vs 行の直下に各 side の**支援国**行（`getWarSideSupporters` = primary 以外の participant。supporter がいる side のみ表示）
  - **Chronicle section**: Polity / House / Person / Province / Holding / War の各 detail panel に、対象 entity の永続履歴（`ChronicleEntry`、§3.14）を表示する共通 component `EntityChronicleSection`。時系列降順・最新 5〜10 件。各 entry は category バッジ（i18n `chronicle.category.*`）+ `[year/W週]` + `templateKey` / `params` を既存 eventRenderer で render する（entityRefs から link は描かない＝役職名・Polity 名は params 側で解決）。section タイトル: 国史（Polity）/ 家の記録（House）/ 履歴（Person）/ 地方史（Province）/ 土地の歴史（Holding）/ 戦争の記録（War）。selector は §4.11。category filter（`showCategories` prop）は受け取れる設計だが、interactive UI（chips）は出さない（office は byPerson 限定で Person panel にしか出ず、他 panel が行政ログで汚れないため不要。§6.62）
  - **Full chronicle panel**: `EntityChronicleSection` は直近 N 件のみ表示するため、対象 entity の**全履歴**を最初から最後まで読むための専用パネル `FullChroniclePanel` を別ウィンドウで開ける。`EntityChronicleSection` に `entityType`/`entityId` を渡すと末尾に「完全版を見る（全N件）」リンクが出て、store の `openChronicleWindow(entityType, entityId)` を呼ぶ。ウィンドウは通常の detail と区別するため windowId に `chronicle:` prefix を付け、同一 entity でも detail と並べて共存できる（`DetailWindow.view: 'detail' | 'chronicle'`）。対象は Chronicle index を持つ 6 種（Person / House / Polity / Province / Holding / War）。パネルは古い順（最初から）/ 新しい順を切替でき、デフォルト古い順。selector が降順を返すため古い順は reverse する。一気に DOM 化せず `PAGE_SIZE`（100）ずつ「さらに表示」で伸ばす（将来のページネーションの土台）。履歴は永続 `chronicleIndex`（War は `params.warId` 全走査）から引くため、**live entity が消滅していても全履歴を閲覧できる**（死亡人物・断絶家・終戦の戦争）。`WindowManager` は `win.view==='chronicle'` を最優先で分岐し、entity 種別を問わず単一 `FullChroniclePanel` で描画する。title だけ live entity から defensive に解決し（消滅時は id / 「戦争の年代記」へ fallback）、entity 不在で blank にしない。行は `EntityChronicleSection` と共有する `ChronicleEntryLine`。i18n は `detail.full_chronicle.*`（ja/en）
  - **Family tree window（家系図）**: 家門の血統を世代ツリーで俯瞰する大窓 overlay。HouseDetail の「家系図を見る」から `openFamilyTree(houseId)` で開く。詳細カード（`openWindows`, z=100+）とは独立に store の `familyTreeHouseId`（null=非表示）で管理し、`App.tsx` で `WindowManager` の直前にマウントする（ノードクリックで開く人物カードが家系図の上に重なる z 順を確保）。画面の大半を占める overlay（`fixed inset-0` の backdrop + `94vw×90vh` のパネル）で、本体は `usePanZoom({ minScale: 0.2 })` によるドラッグパン + ホイールズーム。背面 SVG が親子（実線・直角コネクタ）/ 夫婦（破線）のエッジを、前面に各人物ノードを配置。ノードは既存 `PersonCard` を再利用し、クリックで人物詳細カードを開く。グラフ構築は read-only selector `buildHouseFamilyTree`（§4）。各ノードは家門 H から見た関係（blood / married_in=嫁入り・婿入り / married_out=他家へ婚出）を持ち、married_in/out には相手家門への i18n ラベル付きリンク（`detail.family_tree.relation_*`）を表示する。**全世代**（生存 + 故人 `deceasedMemberIds`）を対象とする。v0.47.4: H が分家・分立で生まれた家（`house.parentHouseId` 有）のとき、その創設者（`house.founderId`）ノードに分家元家への `branchedFromHouseId` を付与し、emerald 枠 + 「{{house}} より分家」リンク（`relation_branched_from` / `legend_branched_from`）を表示する（創設者は H の blood だが由来家を辿れる。婚出は元家側から既に married_out で辿れていた非対称の解消）。本家リンク（親家から子分家一覧への導線）は将来拡張。

レイアウトは v1 の世代行方式で、純関数 `layoutFamilyTree`（`familyTreeLayout.ts`・描画から分離して fast-refresh 制約を満たす）が座標を計算する。**夫婦（父母）をユニットとして隣接配置し、子の親子線は父母の中点から 1 本だけ引く**（同世代の兄弟は同一起点となり sibling bus 状に見える）。**父か母が未設定の場合は「不詳」placeholder パネルを欠けた親の位置に仮置き**して見た目を整える（`detail.family_tree.unknown_parent`）。**夫婦線は live `spouseId` ではなく「共通の子を持つ父母ペア」と `formerSpouseIds`（死別した元配偶者・§3）から再構成して引く**ため、死別（`spouseId` は死亡で clear される）後も両親・元配偶者が夫婦として結ばれる。**子のいない夫婦も** formerSpouseIds から隣接配置・線結びでき、嫁いできて子の無かった配偶者が孤立しない。再婚等で 1 人が複数夫婦に属する場合は子の多い夫婦を primary として隣接配置し、非 primary の配偶者へは行の下を回す U 字の破線で結ぶ（配偶者が孤立して見える問題を解消）。家内婚等で夫婦の選択子世代がずれる場合は couple の世代に揃えて二重配置を防ぐ。色枠（凡例つき）= blood/married_in/married_out。tidy-tree（親を子スパン中央に厳密配置）は将来課題。i18n は `detail.family_tree.*`（ja/en）
- **EventLog**: Chronicle（major/critical）と全イベントの 2 ビュー + Timeline（年別グループ）
  - i18n 対応: イベント種別ラベルをロケール翻訳、数値は `Math.round` で整数表示、`nameParam()` による polity/province/person/role 名のロケール解決
  - EntityLinks: イベントの `entityRefs` から関連エンティティのリンクボタンを表示
  - 日付表示: `year/weekOfYear` 形式
- **Sidebar**: 国家一覧（rank 別）/ 家系一覧（支配家 / 無領家）/ 人物一覧（重要度順）/ 派閥一覧 / 外交劇一覧 / 戦争一覧。ウォッチリスト対応
  - FactionRow: 指導者名・結成日（年/月/月内週）・メンバー数。翻訳済み
  - PlayRow: 種別・ステータス・initiator/defender 名・進展/緊張/期限。翻訳済み
  - WarRow: PlayRow の縮小版。status / attacker・defender 名 / warScore。Active War を一覧表示
- **ConfigPanel**: シミュレーションパラメータをリアルタイム調整
